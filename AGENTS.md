# Legendary Disco Agent Instructions

## Purpose

Legendary Disco is the public play and projection surface of the wider UNUM
ecology. Build small experiences that are enjoyable before they are explained.
Let an effect be real and inspectable without exposing every protected source
that helped inspire it.

## Start here

1. Read `README.md`.
2. Read `RIGHTS.md` before adding code, assets, dependencies, or licenses.
3. Read `PROVENANCE.md` before changing the repository's public boundary.
4. Read the nearest toy README before changing a runnable experience.

## Public boundary

- Every toy must stand on its own without private repositories.
- Do not copy private theory, archives, participant material, save states,
  stewardship keys, character continuity, or unreleased runtime machinery.
- A public effect may be inspired by a private question. Preserve the crossing
  as a scoped pointer and declared loss, not a source dump.
- A toy is not empirical proof, a canonical theory surface, or a complete
  implementation merely because it produces a compelling experience.
- Public visibility does not change the rights posture in `RIGHTS.md`.

## Play and developmental posture

- Make the first interaction legible without requiring project vocabulary.
- Prefer one complete toy over a speculative framework for many toys.
- Preserve pause, reset, reduced-motion behavior, keyboard access, and a clean
  exit from sound or intensity.
- Audio begins only after an explicit user action and starts quietly.
- Avoid rapid full-field flashes, forced camera motion, surprise volume, or
  interaction patterns that trap attention.
- Play may remain funny, strange, beautiful, or unresolved. It does not need to
  become doctrine in order to belong.

## Implementation discipline

- Keep toys self-contained and dependency-light.
- Do not add telemetry, remote APIs, trackers, accounts, or data collection by
  default.
- Name each toy by its demonstrated experience rather than a private subsystem
  it does not implement.
- Separate presentation state from any later imported runtime state.
- Reuse shared code only after a second real consumer exists.
- Record third-party assets, libraries, quotations, and their licenses before
  use. Prefer original code and generated geometry for the first instruments.

## Validation

For an interactive toy, check at minimum:

```text
source syntax
local launch
first render
primary controls
keyboard path
reduced motion
sound opt-in / opt-out
responsive layout
no network dependency
no private-source import
```

## Repository actions

- Keep work bounded and reversible.
- Use feature branches for developed slices until promotion is authorized.
- Stage, commit, push, merge, and release remain separately authorized actions.
- Preserve the exact route back to `main`.

## Tiny lock

```text
Make the strange thing real enough to play with.
Keep the protected roots protected.
Let everyone leave the dance floor freely.
```
